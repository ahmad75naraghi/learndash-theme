# چک‌لیست QA، کارایی و انتشار evented-edu

این سند معیار پذیرش نسخهٔ `2.2.0` و نسخه‌های بعدی است. موارد «خودکار» باید در CI سبز باشند؛ موارد «محیط واقعی» فقط روی staging دارای WordPress، LearnDash، جدول تراکنش و provider پیامک قابل تأییدند.

## ۱) کنترل خودکار قبل از merge

```bash
bash bin/lint.sh
php tests/theme-updater-test.php
php tests/panel-helpers-test.php
python3 tests/static-audit.py
bash bin/build-theme-release.sh /tmp/evented-edu.zip
bash bin/dev-playground.sh
SMOKE_WRITE_PROFILE=1 bash bin/smoke-test.sh http://127.0.0.1:9400 /tmp/wp/site/debug.log
bash bin/test-wordpress-update.sh http://127.0.0.1:9400 /tmp/wp/site
```

- [ ] PHP روی 7.4، 8.1 و 8.3 بدون خطای syntax است.
- [ ] همهٔ JavaScriptها با `node --check` و CSSها از نظر توازن آکولاد پاس می‌شوند.
- [ ] ارجاع asset محلی شکسته وجود ندارد.
- [ ] ZIP فقط یک ریشهٔ `evented-edu/` دارد و Version/Update URI صحیح است.
- [ ] updater، جلوگیری از downgrade/prerelease و نرمال‌سازی zipball پاس است.
- [ ] smoke test واقعی WordPress مسیر خانه، هفت مسیر پنل، تنظیمات مدیریت و assetها را بدون خطای قالب باز می‌کند.
- [ ] AJAX پروفایل ارقام فارسی را ذخیره و تاریخ نامعتبر را رد می‌کند.
- [ ] `Theme_Upgrader` نسخهٔ قدیمی شبیه‌سازی‌شده را جایگزین می‌کند؛ قالب فعال، optionها و slug حفظ و فایل منسوخ حذف می‌شود.

## ۲) ماتریس واکنش‌گرایی

صفحه‌های خانه، آرشیو نوشته، نوشته، آرشیو دوره، دوره، درس، آزمون و تمام مسیرهای `/panel/*` در اندازه‌های زیر بررسی شوند:

| عرض | دستگاه نمونه | پذیرش |
|---:|---|---|
| 320px | موبایل کوچک | بدون اسکرول افقی؛ دکمه‌ها حداقل 44px؛ متن و فرم قابل استفاده |
| 375px | موبایل رایج | هدر، کشو، کارت‌ها، مودال و ناوبری پنل بدون هم‌پوشانی |
| 430px | موبایل بزرگ | تصاویر بدون پرش layout؛ فرم‌ها تک‌ستونه |
| 768px | تبلت | گرید دو ستونه و جدول تراکنش به‌شکل کارت |
| 1024px | تبلت افقی | سایدبارها sticky و محتوای اصلی بدون فشردگی |
| 1440px | دسکتاپ | حداکثر عرض، مگامنو و دو ردیف دوره‌ها صحیح |

- [ ] چرخش portrait/landscape باعث بسته‌ماندن overlay یا قفل اسکرول نمی‌شود.
- [ ] کیبورد مجازی موبایل فیلد فعال و دکمهٔ ذخیره را نمی‌پوشاند.
- [ ] منوی native پنل در موبایل به همهٔ بخش‌ها هدایت می‌کند و خروج در دسترس است.
- [ ] مودال ایمیل، رمز، خروج و رسید با Escape/دکمهٔ بستن بسته می‌شوند.
- [ ] تصاویر، iframeها و رشته‌های طولانی از container بیرون نمی‌زنند.

## ۳) پنل کاربری

### ورود و حساب
- [ ] مهمان هر مسیر پنل با `redirect_to` معتبر به ورود منتقل می‌شود.
- [ ] شماره موبایل readonly است؛ ایمیل معتبر ذخیره و ایمیل تکراری رد می‌شود.
- [ ] تغییر رمز بدون رمز فعلی یا بدون قواعد قدرت رد و با رمز صحیح موفق می‌شود.
- [ ] نام فارسی/انگلیسی نامعتبر در UI و سرور پاک‌سازی می‌شود.
- [ ] تاریخ تولد با ارقام فارسی و عربی ذخیره و تاریخ نامعتبر رد می‌شود.

### دوره‌ها و محتوا
- [ ] پیشخوان فقط چهار دوره را نمایش می‌دهد و لینک «مشاهده همه» صحیح است.
- [ ] پیشرفت دوره با LearnDash یکسان و بین ۰ تا ۱۰۰ است.
- [ ] «دوره‌های من» در بیش از ده مورد صفحه‌بندی می‌شود؛ جستجو روی صفحه جاری کار می‌کند.
- [ ] پیشنهادها تصادفی و سنگین نیستند و دورهٔ ثبت‌نام‌شده پیشنهاد نمی‌شود.
- [ ] حذف علاقه‌مندی optimistic است، خطای شبکه کارت را برمی‌گرداند و حالت خالی صحیح است.
- [ ] گواهی دوره و آزمون فقط برای کاربر مجاز قابل دریافت است.

### تراکنش
- [ ] نبود جدول تراکنش Fatal Error نمی‌سازد و حالت خالی نمایش داده می‌شود.
- [ ] تراکنش‌ها ۲۰تایی صفحه‌بندی می‌شوند.
- [ ] وضعیت‌های موفق، در انتظار، برگشت وجه، لغو و ناموفق درست نمایش داده می‌شوند.
- [ ] فقط تراکنش موفق رسید قابل چاپ دارد و رسید متعلق به همان کاربر است.

## ۴) بودجهٔ کارایی روی staging

Lighthouse موبایل در پنجرهٔ ناشناس، بدون افزونهٔ مرورگر و سه بار اجرا شود؛ میانه ثبت گردد:

- [ ] Performance حداقل **80** و Accessibility حداقل **90**.
- [ ] LCP حداکثر **2.5s**، CLS حداکثر **0.10** و INP حداکثر **200ms**.
- [ ] TTFB صفحهٔ cache‌شده حداکثر **800ms**.
- [ ] asset خارجی ناخواسته، خطای 404 و JavaScript console error وجود ندارد.
- [ ] صفحهٔ غیرپروفایل فایل‌های Jalali Date Picker را دانلود نمی‌کند.
- [ ] تصویر اول هیرو `fetchpriority=high` و تصاویر پایین صفحه lazy هستند.
- [ ] Object/page cache فعال و hit-rate queryهای خانه در Query Monitor بررسی شده است.
- [ ] تصاویر آپلودی با WebP/AVIF و اندازهٔ متناسب تولید می‌شوند.

> امتیاز Lighthouse به سرور، افزونه‌ها، داده و شبکه وابسته است؛ CI فقط قراردادهای کد را کنترل می‌کند و جای تست staging را نمی‌گیرد.

## ۵) آزمون‌های یکپارچهٔ حیاتی

- [ ] خرید موفق/ناموفق، ثبت رکورد تراکنش و دسترسی دوره.
- [ ] تکمیل درس، به‌روزرسانی progress و ادامهٔ دوره.
- [ ] ثبت/تأیید دیدگاه و امتیاز دوره.
- [ ] اعلان داخل سایت، SMS اختیاری و پاک‌سازی retention.
- [ ] PWA: manifest، service worker، offline fallback و نصب موبایل.
- [ ] PDF گواهی با `composer install --no-dev --optimize-autoloader`.
