# حذف WPDM Pro بدون حذف داده‌های دانلود

قالب داده‌های اصلی افزونه را جابه‌جا نمی‌کند. بعد از حذف افزونه، همان ساختارهای موجود ثبت و خوانده می‌شوند:

- post type: `wpdmpro`
- دانلود عمداً هیچ taxonomy ندارد. associationهای قدیمی `wpdmcategory`/`wpdmtag` فقط در runtime جدا می‌شوند و رابطه‌های احتمالی موجود از دیتابیس حذف نمی‌شوند.
- `wpdmcategory` صرفاً برای post type کتابخانه (`lib`) باقی می‌ماند.
- فایل‌ها: `__wpdm_files` و کلیدهای قدیمی `_wpdm_files`
- اطلاعات فایل: `__wpdm_fileinfo`
- حجم بسته: `__wpdm_package_size`
- نسخه: `__wpdm_version`
- آمار دانلود: `__wpdm_download_count`
- تصویر: featured image استاندارد وردپرس (`_thumbnail_id`)
- فیلد استاندارد جدید همهٔ فایل‌ها: `_evented_download_files`

## افزودن فایل جدید

در ویرایش هر دانلود، کادر «فایل‌های دانلود» نمایش داده می‌شود. با دکمهٔ «افزودن فایل» می‌توان هر تعداد فایل از Media Library یا URL خارجی اضافه، حذف و مرتب کرد. همهٔ ردیف‌ها در یک meta_value با کلید `_evented_download_files` ذخیره می‌شوند.

## همگام‌سازی داده‌های قبلی

از مسیر «دانلودها ← همگام‌سازی فایل‌ها» ابزار امن تبدیل را اجرا کنید. این ابزار `__wpdm_files` و `__wpdm_fileinfo` را به ساختار canonical جدید می‌برد، اما هیچ متای WPDM را حذف یا بازنویسی نمی‌کند. اجرای دوبارهٔ ابزار امن و idempotent است. صفحهٔ ویرایش دانلود قدیمی نیز فایل‌های قبلی را قبل از همگام‌سازی نمایش می‌دهد و با اولین به‌روزرسانی آن‌ها را استاندارد ذخیره می‌کند.

## مسیرها

- فهرست و جستجو: `/download/`
- صفحهٔ تکی: `/download/{slug}/`
- فایل‌های داخلی: endpoint عمومی امن قالب که فقط فایل‌های شناخته‌شدهٔ package و واقع در uploads را تحویل می‌دهد.
- فایل‌های خارجی: redirect به URL ذخیره‌شده در متای package.

## ترتیب حذف افزونه

1. ابتدا نسخهٔ جدید قالب را نصب و فعال کنید.
2. از `/download/`، چند صفحهٔ تکی و چند فایل واقعی را آزمایش کنید.
3. از دیتابیس و `wp-content/uploads/download-manager-files/` نسخهٔ پشتیبان بگیرید.
4. WPDM Pro را فقط غیرفعال کنید و دوباره مسیرها را آزمایش کنید.
5. پس از اطمینان، افزونه را حذف کنید. پوشهٔ `download-manager-files` و رکوردهای `wpdmpro`/`__wpdm_*` نباید حذف شوند.

طبق تصمیم سایت، packageهای منتشرشده عمومی‌اند. داده‌های رمز/role قبلی حذف نمی‌شوند اما در endpoint جدید اعمال نمی‌شوند.
